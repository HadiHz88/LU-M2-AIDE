Broadcasting

When two shapes differ, NumPy compares them from the right. Matching sizes, or a missing dimension, are fine, and the smaller array is reused across the missing dimension. Nothing is actually copied.

Does np.empty((3, 4)) give zeros?
No. It gives uninitialized "garbage" memory. Use np.zeros for zeros.
np.arange(10, 50, 10) vs np.linspace(10, 50, 5)?
[10 20 30 40] (step, stop excluded) vs [10. 20. 30. 40. 50.] (count, stop included).
np.amin([[7,2],[3,4],[5,6]], axis=1)?
[2 3 5]: one minimum per row. With axis=0: [3 2].
Shape of x * y for x (2,) and y (3, 2)? What makes it work?
(3, 2), by broadcasting: x is reused on each of the 3 rows. Element-wise, not matrix multiplication.

In place, and memory shared with NumPy

A method ending in _ changes the tensor itself: t.add_(5), t.sub_(3), t.t_(), t.copy_(5). Without the underscore, a new tensor is returned and t is untouched. In-place ops save memory but are discouraged around gradients.

t = torch.ones(5)
n = t.numpy()          # n shares t's memory
t.add_(2)              # t: tensor([3., 3., 3., 3., 3.])   n: [3. 3. 3. 3. 3.]

n2 = np.ones(5)
t2 = torch.from_numpy(n2)
np.add(n2, 1, out=n2)  # t2: tensor([2., 2., 2., 2., 2.], dtype=torch.float64)

float64 appears because NumPy's default decimal type is float64 and from_numpy keeps it. PyTorch's default is float32, which isn't printed.

from_numpy (and t.numpy()). torch.tensor always copies.
x has shape (2, 3). torch.cat([x, x], dim=1)?

What does the trailing _ in add_ mean?
In-place: it modifies the tensor itself instead of returning a new one.
Lesson 5 · Labs 5–6

Autograd: gradients, backward and step

torch.autograd is PyTorch's automatic differentiation engine. It works out which way to move every weight to reduce the error.

A gradient is a slope

One weight w, loss = (w − 3)². The best w is 3. The gradient 2(w − 3) is the slope at the current w. Positive slope: decrease w. Negative slope: increase w. Gradient descent always steps against the slope: w_new = w − lr × gradient.

Stepwlossgradientupdate (lr = 0.25)
054+45 − 1 = 4
141+24 − 0.5 = 3.5
23.50.25+13.5 − 0.25 = 3.25

Tracking: requires_grad and grad_fn

Every operation on a tracked tensor is recorded in a computational graph. A tensor produced by an operation gets a grad_fn: a receipt of how it was made. Tensors you create yourself are leaves and have grad_fn = None. The output of an operation requires grad if any input does.

x = torch.ones(5)                          # input
y = torch.zeros(3)                         # target
w = torch.randn(5, 3, requires_grad=True)
b = torch.randn(3, requires_grad=True)
z = torch.matmul(x, w) + b                 # z.grad_fn = <AddBackward0>
loss = torch.nn.functional.binary_cross_entropy_with_logits(z, y)

backward() computes, step() changes

loss.backward()

Walks the graph backward (chain rule) and stores ∂loss/∂w in w.grad for every leaf with requires_grad=True. Values do not change. Gradients are added to what is already in .grad.

torch.optim.SGD(params, lr, momentum=0)
params
the tensors to update: [w, b] or net.parameters()
lr
learning rate: the step size
momentum
keeps some of the previous step's direction (0.9 in Lab 9)

optimizer.step() applies w ← w − lr × w.grad. optimizer.zero_grad() empties every .grad.

Moment (Lab 5 numbers)w[0][0]w.grad[0][0]
after creating w0.2070None
after loss.backward()0.2070 (same)0.3062
after optimizer.step(), lr = 0.0010.20670.3062

Check by hand (Lab 6): with a = [2., 3.], b = [6., 4.] and Q = 3a³ − b², the derivatives are ∂Q/∂a = 9a² and ∂Q/∂b = −2b. After Q.backward(gradient=torch.tensor([1., 1.])): a.grad = [36., 81.], b.grad = [-12., -8.]. (The gradient= argument is needed because Q is a vector, not a single number.)

Freezing and switching tracking off

  • requires_grad=False freezes a tensor: its .grad stays None and optimizer.step() skips it. Lab 5's example: w frozen, b trainable → only b changes.
  • with torch.no_grad(): switches tracking off for a block. Use it when you only need predictions (testing): no graph, less memory, faster.
z = torch.matmul(x, w) + b
print(z.requires_grad)      # True
with torch.no_grad():
    z = torch.matmul(x, w) + b
print(z.requires_grad)      # False
Right after loss.backward(), have w's values changed?
No. Only w.grad is filled. optimizer.step() changes the values.
Why does z have a grad_fn but x doesn't?
z was produced by operations on tensors that require grad, so autograd recorded how it was made. x is a leaf you created directly.
w frozen (requires_grad=False), b trainable. After backward + step?
w.grad is None and w is unchanged; only b is updated. No error.
Shape of w.grad when w is 5 × 3?
torch.Size([5, 3]): one slope per weight.

Layers and activation functions

A neural network is a stack of simple functions with learnable weights. These are the pieces you stack.

import torch.nn as nn
import torch.nn.functional as F

Linear (fully connected)

nn.Linear(in_features, out_features, bias=True)
in_features
length of each input vector
out_features
length of each output vector

Computes y = x·Aᵀ + b. Only the last dimension changes: Lab 7 feeds a (3, 2, 4) tensor into nn.Linear(4, 3) and gets (3, 2, 3).

Convolution: Conv2d

nn.Conv2d(in_channels, out_channels, kernel_size, stride=1, padding=0)
in_channels
layers in the input: 3 for RGB, 1 for grayscale
out_channels

kernel_size

Output sizeh_out = (h_in + 2p − D(k − 1) − 1) / s + 1
With dilation D = 1: h_out = (h_in + 2p − k) / s + 1. For 32, k = 5, p = 0, s = 1: (32 − 5)/1 + 1 = 28.

Lab 7's small example: a 1 × 4 × 4 input through nn.Conv2d(1, 1, kernel_size=2) gives 1 × 3 × 3, because (4 − 2)/1 + 1 = 3.

Max pooling

nn.MaxPool2d(kernel_size, stride=None)

defaults to kernel_size. MaxPool2d(2, 2) halves height and width.

Function version: F.max_pool2d(x, 2) or F.max_pool2d(x, (2, 2)).

Activation functions

NameFormulaIn PyTorch
ReLUmax(0, x)F.relu(x)

Softmax turns raw scores (logits) into probabilities between 0 and 1 that sum to 1: scores [2.0, 1.0, 0.1] → [0.659, 0.242, 0.099]. The order never changes, so the biggest score is always the biggest probability.

What do the numbers in nn.Conv2d(3, 6, 5) mean?
3 input channels (RGB), 6 filters (6 output maps), 5 × 5 kernel. Defaults: stride 1, padding 0.
Output size of a 32 × 32 image after nn.Conv2d(3, 6, 5)?
6 × 28 × 28: (32 − 5)/1 + 1 = 28.
Which formula is ReLU? Sigmoid? Softmax?
max(0, x); 1/(1 + e−x); exi/Σexj.
Lesson 7 · Labs 7 + 9

Building a network with nn.Module

A network is a Python class: __init__ creates the layers and forward says how data flows through them. Then you track the shape at every step.

The class, line by line

class Net(nn.Module):                     # 1. a new kind of nn.Module
    def __init__(self):                   # 2. runs once, at net = Net()
        super(Net, self).__init__()       #    set up nn.Module first (required)
        self.conv1 = nn.Conv2d(3, 6, 5)   # 3. layers are stored on self
        self.pool  = nn.MaxPool2d(2, 2)
        self.conv2 = nn.Conv2d(6, 16, 5)
        self.fc1   = nn.Linear(16 * 5 * 5, 120)
        self.fc2   = nn.Linear(120, 84)
        self.fc3   = nn.Linear(84, 10)

    def forward(self, x):                 # 4. runs at net(x)
        x = self.pool(F.relu(self.conv1(x)))
        x = self.pool(F.relu(self.conv2(x)))
        x = x.view(-1, 16 * 5 * 5)        # flatten
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        x = self.fc3(x)                   # raw scores: no softmax
        return x

net = Net()
outputs = net(images)                     # calls forward

You only write forward. The backward pass is created automatically by autograd. Each layer's "in" number equals the previous layer's "out": conv1 out 6 → conv2 in 6, fc1 out 120 → fc2 in 120.

Tracking the shape

  • Conv, kernel 5, no padding: size − 4. Channels become the number of filters.
  • MaxPool2d(2, 2): size ÷ 2 (rounded down). Channels stay.
  • ReLU: no shape change.
  • view: flattens 16 × 5 × 5 = 400, which must equal fc1.in_features.
x.view(*shape)

Same data, new shape, no copy (shares memory). The total number of elements must stay the same. One size may be -1: "work it out". torch.arange(6).view(2, 3) → 2 × 3; x.view(-1, 400) on [16, 16, 5, 5] → [16, 400].

Lab 7's own network (grayscale, 3 × 3 kernels) on a 1 × 32 × 32 input: conv 3 → 30, pool → 15, conv 3 → 13, pool → 6 (13 ÷ 2 rounded down). So fc1 takes 16 × 6 × 6 = 576, which matches the printed torch.Size([1, 576]).

Other things Lab 7 shows

  • net.parameters() gives every weight and bias tensor. For Lab 7's net that's 10 (5 layers × weight + bias); params[0].size() is [6, 1, 3, 3].
  • torch.nn only accepts batches: [N, C, H, W]. For a single image, add a fake batch dimension with input.unsqueeze(0).
  • A loss compares output and target: criterion = nn.MSELoss(), then loss = criterion(output, target).
  • The full update: optimizer.zero_grad(), forward, loss, loss.backward(), optimizer.step(). optim.Adam(net.parameters(), lr=0.01) is used the same way as SGD.
Do you write a backward() method in your Net class?
No. You only define forward; autograd builds backward.
Input [16, 3, 32, 32]: shape after each stage?
conv1 [16, 6, 28, 28] → pool [16, 6, 14, 14] → conv2 [16, 16, 10, 10] → pool [16, 16, 5, 5] → view [16, 400] → fc3 [16, 10].
Why must fc1 have 400 input features?
After the last pool each image is 16 × 5 × 5 = 400 numbers; Linear's in_features must equal the flattened length.

Training and testing a classifier

Everything comes together on CIFAR-10: 10 classes of 3 × 32 × 32 color images. This lesson is worth the most points.

The five steps of Lab 9

  1. Load and normalize CIFAR-10: Compose([ToTensor(), Normalize((0.5,0.5,0.5), (0.5,0.5,0.5))]); train loader batch 16, shuffled; test loader batch 4; num_workers=2.
  2. Define the CNN: the Net class from Lesson 7.
  3. Define the loss and optimizer (below).
  4. Train: 10 epochs of the loop below.
  5. Test on the test set: accuracy 56%.

Loss and optimizer

nn.CrossEntropyLoss()

For classification. Takes raw scores [batch, 10] and labels [batch], applies softmax internally, and returns the mean loss over the batch.

optim.SGD(net.parameters(), lr=0.01, momentum=0.9)

Lab 9's exact values. The official PyTorch tutorial uses 0.001; your lab uses 0.01.

The training loop

for epoch in range(n_epochs):                   # 10 times
    running_loss = 0.0
    for i, data in enumerate(trainloader, 0):   # 3,125 times per epoch
        inputs, labels = data
        optimizer.zero_grad()                   # 1. clear
        outputs = net(inputs)                   # 2. predict  [16, 10]
        loss = criterion(outputs, labels)       # 3. score    one number
        loss.backward()                         # 4. blame    fills .grad
        optimizer.step()                        # 5. fix      weights change
        running_loss += loss.item()             # .item(): tensor → Python number
        if i % 2000 == 1999:                    # every 2000 batches
            print('[%d, %5d] loss: %.3f' % (epoch + 1, i + 1, running_loss / 2000))
            running_loss = 0.0

Why zero_grad, once per batch

.grad is a whiteboard. backward() adds its number to the board without erasing it; step() reads the board. Follow one weight:

MomentWith zero_grad()Without
batch 0: backward gives +20 + 2 = +20 + 2 = +2
batch 0: step reads+2 ✓+2 ✓
batch 1: wipe0(skipped) still +2
batch 1: backward gives −10 − 1 = −12 − 1 = +1
batch 1: step reads−1 ✓ increase w+1 ✗ decrease w

So: once per batch, at the start of the inner loop. Not per image: the 16 images give one averaged loss and one gradient. Not per epoch: step() runs every batch, so the board must be clean every batch.

Order of the 5 lines in each iteration?
optimizer.zero_grad() → outputs = net(inputs) → loss = criterion(outputs, labels) → loss.backward() → optimizer.step().
What goes wrong without zero_grad()?
Gradients accumulate across batches, so step() uses a growing sum of old gradients: wrong, unstable updates.
What is in predicted after _, predicted = torch.max(outputs, 1)?
For each image, the index of its highest score = the predicted class.
Lab 9: loss, lr, momentum, batch sizes, epochs, accuracy?
CrossEntropyLoss; 0.01; 0.9; 16 train / 4 test; 10 epochs; 56% (chance 10%).
One epoch is…?
One complete pass of the entire training set through the model.
Lesson 10 · Lab 10

Data augmentation

More variety for free: make new training images by changing existing ones, so the model learns what stays the same.

What and why

Data augmentation creates new training examples by modifying existing ones (flip, crop, rotate, recolor) without changing their meaning: the label stays correct. Models are sensitive to small details; seeing many versions of the same thing teaches them the patterns that stay consistent, which builds robustness on unseen data. In PyTorch it happens in the Dataset's transform, usually a Compose.

Rules from the lab

  • Visualizing? Use shuffle=False "so that we always see the same images" and can compare them.
  • Keep the image size. The network expects a fixed size (fc1 = 400 depends on 32 × 32). RandomCrop with padding keeps it.
  • Augment training data only. The transfer-learning script uses flips, rotation and ColorJitter for training, but only ToTensor + Normalize for validation.
  • Don't Mixup unrelated classes (dog + airplane) blindly.
  • For display, data[0].swapaxes(0,2).swapaxes(0,1) turns C × H × W into H × W × C.
What makes an augmentation good rather than harmful?
It adds variety but keeps the meaning: the label must still be correct. A "6" rotated too far reads as "9".
RandomCrop belongs to which family? Cutout? ColorJitter? Mixup?
Geometric; occlusion; color; mixing.
Which transform gives a single-channel image?
transforms.Grayscale(num_output_channels=1)

False, so the same images appear each run.
Lesson 11 · Lab 6 + transfer-learning script

Transfer learning, train and eval mode

Reuse a network already trained on millions of images, retrain only its last layer, and switch it correctly between training and testing.

model = torchvision.models.resnet18(weights=None)        # the structure
model.load_state_dict(torch.load(PATH))                  # pretrained weights (ImageNet, 1000 classes)

for param in model.parameters():                         # freeze everything
    param.requires_grad = False

model.fc = nn.Linear(model.fc.in_features, 10)           # new head: 512 → 10, trainable by default
optimizer = optim.Adam(model.fc.parameters(), lr=0.001)  # optimize only the head
  • resnet18(weights=ResNet18_Weights.DEFAULT) downloads ImageNet weights; weights=None builds the same structure with random weights.
  • state_dict: a Python dictionary mapping each layer name to its tensor (conv1.weight: [64, 3, 7, 7], …). torch.save / load_state_dict use it.
  • The new layer is created after the freezing loop, so it is trainable. The script's head is nn.Sequential(nn.Dropout(0.5), nn.Linear(model.fc.in_features, 10)).
  • Fine-tuning: also unfreeze the last block, for param in model.layer4.parameters(): param.requires_grad = True.

train(), eval() and no_grad()

PhaseCallDropoutBatchNormGradients
trainingmodel.train()on (drops neurons)uses batch stats, updates averagestracked
validation / testmodel.eval()offuses saved averagesstill tracked!
validation / testwith torch.no_grad():(no effect)(no effect)off: less memory, faster
for epoch in range(num_epochs):
    model.train()                          # training phase
    for images, labels in train_loader:
        outputs = model(images)
        loss = criterion(outputs, labels)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

    model.eval()                           # validation phase
    with torch.no_grad():
        for images, labels in val_loader:
            outputs = model(images)
            _, preds = torch.max(outputs, 1)

Forgetting them: no eval() → Dropout and BatchNorm keep training behaviour, so test results are noisy and unreliable. No no_grad() → correct results but wasted memory and time. No train() after validating → the next epoch trains with Dropout off and BatchNorm frozen. The Lab 9 net has neither Dropout nor BatchNorm, but ResNet has BatchNorm, which is why the script calls both.

How do you freeze a pretrained network's layers?
for param in model.parameters(): param.requires_grad = False, then replace model.fc with a new trainable layer.
Does model.eval() stop gradient tracking?
No. It changes Dropout/BatchNorm behaviour. torch.no_grad() stops tracking. Use both when testing.
What is a state_dict?
A dictionary: layer name → parameter tensor. It's what you save and load.

True/False traps from the mock

  • np.empty gives zeros → False (garbage).
  • backward() computes and updates → False (step updates).
  • You must write backward() in your nn.Module → False (automatic).
  • Lab 9's forward ends with softmax → False (raw logits).
  • Visualize augmentations with shuffle=True → False.
  • from_numpy shares memory → True. ToTensor scales to [0, 1] → True.
  • linspace includes the end, arange doesn't → True. Augmentation must keep the label → True.
  • Absolute words ("all", "both", "must") often signal False, but check each one.
