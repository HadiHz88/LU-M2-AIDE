Merge-request rules and branch protection

Do
  1. Settings → Merge requests: Merge method Fast-forward merge; squash Encourage; tick Pipelines must succeed and All threads must be resolved. Save.
  2. Settings → Repository → Protected branches, main: Allowed to push and merge → No one; keep Allowed to merge → Maintainers.
Say
Fast-forward keeps the history linear. A merge request can only be merged if its pipeline passes. Nobody can push to main directly any more, so every change goes through a merge request.

Code review through a merge request

⎇ features/improve-docspassed → mergedpipeline ~1.5 min
Do
  1. Web IDE: add a first line # Learn GitLab CI/CD pipeline to .gitlab-ci.yml → Commit.
  2. GitLab refuses main and offers a new branch: name it features/improve-docs.
  3. Create MR, add a description, create it. Show the merge button disabled while the pipeline runs, then Merge.
Say
The direct commit to main is blocked, so the change goes on a feature branch and a merge request. Once the pipeline is green, the merge is allowed. In a team, someone else would review and approve first.

.gitlab-ci.ymlpipelines/11-netlify-deploy-smoke.yml 
# Part 2, step 3 (branch features/netlify) — real deployment + smoke test.
# Moved to a "deploy" stage so it runs AFTER the build and receives build/.
# Fixes vs the PDF:
#   * node:22-alpine, because the PDF's `apk add curl` does not work on the
#     Debian-based node:23-slim image.
#   * --no-build: current netlify-cli builds before deploying by default; we
#     deploy the artifact that build_website already produced.
#   * the smoke test hits YOUR site, not the professor's.
stages:
  - build
  - test
  - deploy

variables:
  NETLIFY_SITE_ID: "REPLACE-WITH-YOUR-SITE-ID"
  NETLIFY_SITE_NAME: "REPLACE-WITH-YOUR-SITE-NAME"   # the part before .netlify.app

build_website:
  image: node:23-slim
  stage: build
  script:
    - node --version
    - npm --version
    - npm ci
    - npm run build
  artifacts:
    paths:
      - build/

test_artifact:
  image: alpine
  stage: test
  script:
    - test -f build/index.html

unit_tests:
  image: node:22-alpine
  stage: test
  script:
    - npm ci
    - npm test
  artifacts:
    when: always
    reports:
      junit: reports/junit.xml

netlify_deploy:
  stage: deploy
  image: node:22-alpine
  script:
    - npm install -g netlify-cli@27
    - netlify --version
    - apk add --no-cache curl
    - netlify status
    - echo $NETLIFY_SITE_ID
    - netlify deploy --alias uat --dir build --no-build
    - curl -fsS "https://uat--${NETLIFY_SITE_NAME}.netlify.app/" | grep 'GitLab'

  - test

  - deploy_prod

Part 3

Deploy to AWS

Sync the same build to an S3 bucket configured as a public static website.

1

IAM user and access key

Do
  1. AWS console → IAM → Users → gitlab → attach AmazonS3FullAccess (or the policy in aws/iam-s3-deploy-policy.json).
  2. Create access key → Command Line Interface → download the CSV. Don't show the secret on camera.
Say
The pipeline needs its own AWS identity. This IAM user can only use S3, and its access key goes into GitLab as a secret.
2

S3 bucket as a static website

Do
  1. S3 → Create bucket: general purpose, unique name, us-east-1, untick Block all public access, acknowledge.
  2. Permissions → Bucket policy → paste aws/s3-bucket-policy.json with your bucket name.
  3. Properties → Static website hosting → Enable, index document index.html. Copy the endpoint URL.
Say
The bucket is public read-only, so anyone can view the site but only our IAM user can write to it. Static website hosting serves index.html at this endpoint.
3

AWS keys as CI/CD variables

Do
  1. GitLab → Settings → CI/CD → Variables: AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY (Masked).
  2. Show the variable list with the three secrets.
Say
The AWS CLI reads these exact variable names, so the job needs no login step.

.gitlab-ci.ymlpipelines/13-aws-s3-final.yml 
# Part 3 (branch features/aws, then merge request into main) — FINAL PIPELINE.
# Same project as Parts 1–2 (instead of the PDF's second fork): the Netlify
# jobs stay, and a deploy_aws stage pushes the same build/ to an S3 bucket
# configured for static website hosting.
#
# Secret variables (Settings > CI/CD > Variables, Masked): AWS_ACCESS_KEY_ID,
# AWS_SECRET_ACCESS_KEY, NETLIFY_AUTH_TOKEN. The AWS CLI reads the AWS ones by
# their exact names. AWS_DEFAULT_REGION is not secret, so it lives here.
stages:
  - build
  - test
  - deploy_uat
  - deploy_prod
  - deploy_aws

variables:
  VITE_APP_VERSION: $CI_COMMIT_SHORT_SHA
  NETLIFY_SITE_ID: "REPLACE-WITH-YOUR-SITE-ID"
  NETLIFY_SITE_NAME: "REPLACE-WITH-YOUR-SITE-NAME"
  AWS_S3_BUCKET: "REPLACE-WITH-YOUR-BUCKET-NAME"
  AWS_DEFAULT_REGION: "us-east-1"

build_website:
  image: node:23-slim
  stage: build
  script:
    - node --version
    - npm --version
    - npm ci
    - npm run build
  artifacts:
    paths:
      - build/

test_artifact:
  image: alpine
  stage: test
  script:
    - test -f build/index.html

unit_tests:
  image: node:22-alpine
  stage: test
  script:
    - npm ci
    - npm test
  artifacts:
    when: always
    reports:
      junit: reports/junit.xml

netlify_uat:
  stage: deploy_uat
  image: node:22-alpine
  rules:
    - if: $CI_COMMIT_REF_NAME == $CI_DEFAULT_BRANCH
  before_script:
    - npm install -g netlify-cli@27
    - apk add --no-cache curl
  script:
    - netlify --version
    - netlify status
    - netlify deploy --alias uat --dir build --no-build
    - curl -fsS "https://uat--${NETLIFY_SITE_NAME}.netlify.app/" | grep 'GitLab'
    - echo "End of UAT deployment"

netlify_prod:
  stage: deploy_prod
  image: node:22-alpine
  rules:
    - if: $CI_COMMIT_REF_NAME == $CI_DEFAULT_BRANCH
      when: manual
  before_script:
    - npm install -g netlify-cli@27
    - apk add --no-cache curl
  script:
    - netlify --version
    - netlify status
    - netlify deploy --prod --dir build --no-build
    - curl -fsS "https://${NETLIFY_SITE_NAME}.netlify.app/" | grep 'GitLab'
    - echo "End of production deployment"

aws_s3:
  stage: deploy_aws
  image:
    name: amazon/aws-cli
    entrypoint: [""]          # the image's entrypoint is `aws`; GitLab needs a shell
  rules:
    - if: $CI_COMMIT_REF_NAME == $CI_DEFAULT_BRANCH
  needs:
    - build_website           # start as soon as the build exists (doesn't wait for the manual prod job)
  script:
    - aws --version
    - aws s3 ls
    - echo "Bucket content BEFORE upload:"
    - aws s3 ls "s3://$AWS_S3_BUCKET" --recursive
    - aws s3 sync ./build/ "s3://$AWS_S3_BUCKET" --delete
    - echo "Bucket content AFTER upload:"
    - aws s3 ls "s3://$AWS_S3_BUCKET" --recursive
    - echo "Website -> http://$AWS_S3_BUCKET.s3-website-$AWS_DEFAULT_REGION.amazonaws.com/"

aws_smoke_test:
  stage: deploy_aws
  image: alpine
  rules:
    - if: $CI_COMMIT_REF_NAME == $CI_DEFAULT_BRANCH
  needs:
    - aws_s3
  script:
    - wget -qO- "http://$AWS_S3_BUCKET.s3-website-$AWS_DEFAULT_REGION.amazonaws.com/" | grep 'GitLab'
    - echo "S3 website is up"
